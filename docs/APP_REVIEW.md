# Wardrobe UI, UX and functionality review

Reviewed 11 November 2026 against application source commit `d7b0c9b` and the supplied PRD. Review only: no application fixes or database changes were applied.

## Evidence and limits

- Inspected all current views and event handlers: landing, navigation, authentication, inventory, item editor, archive/search/filter/export, outfit studio and preferences; inspected renderer, recommendation engine and PWA files.
- Reproduced recommendation defects directly against the sample inventory with a read-only Node harness.
- Calculated representative contrast ratios from the checked-in CSS foreground/background values.
- Attempted live Chrome access. Browser plugin failed to read requirements; native keyboard navigation reached the URL but Chrome reported `ERR_TUNNEL_CONNECTION_FAILED`. The managed preview relay also timed out on port 4173. Consequently no live screen, signed-in flow, device viewport, keyboard focus order or rendered alignment was visually verified in this review. Source-proven CSS defects are distinguished below from responsive design recommendations requiring visual confirmation.
- Existing build/auth/domain/database tests passed in the preceding delivery. They are not browser or accessibility tests, and passing them does not negate these review findings.

Severity: P1 = fix before calling the app a polished usable v1; P2 = next usability/functionality iteration; P3 = later enhancement or validation. These are product priorities, not claims of security exploits.

| UI-04 | P1       | **Small text links and icon controls have weak touch sizing.** Auth links are 9 px with zero padding; text buttons use only 5 px vertical padding; close controls lack a fixed touch box.                                                                              | Use at least 44×44 px as the design target for touch controls, with spacing between adjacent actions. | UI-05 | P1       | **Mobile input zoom risk.** 12 px input text can cause focus zoom in mobile Safari.                                                                                                                                                                                    | Set input/select/textarea text to at least 16 px on mobile; validate on an actual iPhone rather than disabling zoom.                                                                                                |
| UI-06 | P2       | **Heading/action alignment is brittle.** Mobile Add a piece is manually pushed down with `margin-top:30px` alongside a 45 px heading.                                                                                                                                  | Use a grid or stacked heading/actions at narrow widths. ## UX and reliability

| ID    | Priority | Finding and evidence                                                                                                                                                                                              | Suggested fix                                                                                                                                                                                    |
| ----- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| UX-01 | P1       | **A loading failure is presented as missing access.** `wardrobe_bootstrap` error leaves access=false; once busy=false, the main screen says the account needs an invitation.                                      | Separate loading, failed, not-authorized and empty states. Show retry for network/API failure; reserve access messaging for a successful access=false response.                                  |
| UX-02 | P1       | **Drafts can be lost without warning.** Editor closes on Escape/backdrop/Cancel without a dirty check. Auth identity changes reset editor and preferences.                                                        | Preserve unsaved drafts through recoverable interruptions or confirm discard; distinguish saved preference values from unsaved form values. Avoid storing sensitive drafts indefinitely.         |
| UX-03 | P1       | **Sign-in links can open the finance app.** Current OTP screen explicitly warns about it; Wardrobe redirects/Google flow remain unverified.                                                                       | Keep email code primary. Verify/add Wardrobe's exact callback URL while preserving shared Auth configuration, then support reliable links/Google. Do not reset shared passwords as a workaround. |
| UX-04 | P2       | **OTP resend looks available while cooldown is active.** Button stays enabled; clicking produces a wait error.                                                                                                    | Display a live countdown and disable resend until allowed; use generic, helpful delivery/error messaging without revealing account existence.                                                    |
| UX-05 | P2       | **Filters make empty states misleading.** Selecting an empty category with no search shows “Your wardrobe starts with one piece” even if other categories contain items.                                          | Use distinct first-use, empty-category, no-results and empty-archive messaging, with Clear filters where appropriate.                                                                            |
| UX-06 | P2       | **Saved pieces can disappear from the visible results.** Adding from archive view or a different category keeps the current filters, while new items are active by default.                                       | After save, reveal the saved piece or explicitly say which filter hides it and offer View piece.                                                                                                 |
| UX-07 | P2       | **Page navigation is only component state.** Reload returns to wardrobe; browser Back does not navigate studio/preferences; logged-out navigation can change the active highlight while showing the same landing. | Introduce meaningful URLs and explicit logged-out navigation behaviour. Support Back/reload and deep links.                                                                                      |
| UX-08 | P2       | **New users receive no guided path to a useful wardrobe.** Summary's “ways to start” is actually category count, not outfit possibilities.                                                                        | Add a skippable 10–15-item starter checklist and first-outfit milestone. Rename the metric to Categories or calculate real combinations.                                                         |
| UX-09 | P2       | **App-wide busy/error state mixes unrelated operations.** Global errors can remain visible across flows; cancelled bootstrap completion can leave busy stale.                                                     | Use operation-specific request status/error handling, cancellation guards and reliable cleanup. Add a retryable top-level error boundary.                                                        |
| UX-10 | P2       | **Permanent delete uses browser confirm, with no recovery.** Archive is available but buried in the edit form.                                                                                                    | Make Archive a clear normal action; use a named confirmation dialog for permanent delete. Consider short-lived trash/undo as an enhancement.                                                     |

## Functionality and scope

| ID    | Priority | Finding and evidence                                                                                                                                                                                                                    | Suggested fix                                                                                                                                                                                                       |
| ----- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FN-01 | P1       | **Occasion is not enforced.** `suggest()` sorts by formality but never rejects incompatible pieces. A formal request using sample data produced a smart shirt, casual jeans and casual sneakers, with no occasion warning.              | Define occasion compatibility and completeness rules; filter or penalize mismatches, explain compromises, and return a transparent partial outfit when no appropriate complete look exists.                         |
| FN-02 | P1       | **Regenerate loops between the first two candidates.** Only the immediately previous signature is excluded. Five sample requests returned A,B,A,B,A despite four possible base combinations.                                            | Track recently shown signatures or traverse a ranked/shuffled candidate pool; explain when alternatives are exhausted.                                                                                              |
| FN-03 | P1       | **Preferences are stored but unused.** Engine consumes items, occasion and previous signature only; it ignores preferred/avoided colours, fit, climate and style.                                                                       | Implement meaningful constraints/ranking, with user-controlled hard exclusions versus soft preferences. Avoid implying personalised recommendations until this works.                                               |
| FN-04 | P1       | **Central v1 capture flow is missing.** Manual form exists, but no natural-language extraction, photo detection, multiple-item review or temporary image lifecycle.                                                                     | Implement plain-text capture and editable review first; then authenticated vision processing, consent, provider retention review, bounded quotas/retries and guaranteed cleanup. Keep manual fallback.              |
| FN-05 | P1       | **Recommendations cannot learn.** No persisted recommendation/item links, rationale, like/dislike or optional reason, despite v1 PRD requirements.                                                                                      | Persist validated recommendations and feedback; show a short rationale and feed feedback into future ranking. Validate owner/active inventory references server-side when adding persistence/AI.                    |
| FN-06 | P2       | **Renderer loses garment identity.** All bottoms are trouser-shaped, every one-piece is dress-shaped, all footwear is one sneaker, and all accessories fall back to a belt-shaped object. Fit/length/material do not affect the visual. | Add category/subtype templates for shorts, skirts, trousers, dresses/jumpsuits and common footwear; use a visibly generic labelled fallback for unsupported items. No permanent photo storage is needed.            |
| FN-07 | P2       | **Item entry has weak structured taxonomy.** Subtype/fit are free text; many relevant PRD fields are absent. Colour/formality defaults can be saved without conscious confirmation.                                                     | Use category-specific subtype controls, Unknown defaults where appropriate, and progressive disclosure for sleeve/length/material/season/secondary colours. Normalize stored values while retaining display labels. |
| FN-08 | P2       | **Privacy/account management is incomplete.** Export exists, but no visible privacy page or Wardrobe-only delete-data flow.                                                                                                             | Add privacy/settings and scoped deletion that preserves finance data and shared Auth identity. Export future feedback/recommendations once those entities exist.                                                    |
| FN-09 | P2       | **Installable PWA is online-only.** Service worker's fetch handler does nothing; no offline status/install guidance or offline wardrobe browsing.                                                                                       | Give an explicit online/offline status and install guidance. Offline browsing is optional per PRD and should be added only with a deliberate private-data caching/logout policy. Never promise offline AI.          |

## Recommended delivery order

1. **Usability/reliability pass:** fix horizontal controls, typography/contrast/tap targets, responsive heading/actions, correct error/empty states, draft protection, and OTP countdown. Validate browser/mobile flows before declaring this pass complete.
2. **Make current recommendations trustworthy:** occasion constraints, non-repeating candidate selection, preferences, missing-slot explanations, rationale and feedback persistence.
3. **Complete the v1 capture promise:** text extraction/review, then photo/multiple-item capture with the agreed privacy and provider controls.
4. **Expand renderer and account controls:** accurate subtype templates, structured optional attributes, privacy/scoped deletion, install guidance.
5. **Keep later scope later:** saved outfits, wishlist/gap insights are v1.5; shopping links, weather, wear tracking and cost-per-wear remain v2 unless the user deliberately reprioritizes.

The current build is a useful manual-inventory foundation, not the finished AI wardrobe described in the PRD. Improve its usability and recommendation correctness before adding shopping/weather/social scope.

## Implementation follow-up — 11 November 2026

User authorized the fixes and then requested an outfit composition without a humanoid. The update delivers one coordinated flat-lay canvas with individually labelled/clickable garments, rather than three separate cards.

- UI-01–UI-10: horizontal control direction, readable type scale, darker text, touch sizing, responsive headings/actions, SVG icons, normalized card title space, accessible selected/modal state, and bundled fonts implemented. Real device/visual verification is still required.
- UX-01, UX-02, UX-04–UX-09: retryable bootstrap errors separate from no-access; discard/before-unload safeguards; same-identity session draft retention; OTP cooldown; contextual empty states and filter reset; saved-item visibility; hash navigation; starter guide; isolated loading status and error boundary implemented.
- UX-10: explicit archive action and named permanent-delete confirmation implemented; undo/trash is not added.
- FN-01–FN-03 and FN-05: strict formal/smart rules, nonrepeating candidate history, preferences, rationale, server-validated records and persisted ratings implemented. Ranking uses known structured attributes; it does not infer weather, season or taste beyond entered data/feedback.
- FN-04: local word-based multi-description proposal/review added. This is not full AI natural-language or photo extraction. No photos/AI requests are transmitted.
- FN-06/FN-07: category-specific subtype choices, Unknown defaults, optional season/material/length/style tags, and distinct shorts/skirt/jumpsuit/boot/heel/sandal/accessory silhouettes added. Not all optional attributes alter the vector drawing.
- FN-08/FN-09: privacy notice, full Wardrobe export, typed-confirmation Wardrobe-only clearing, online status and install guidance added. Offline inventory caching remains deliberately deferred.
- UX-03 remains open: shared Auth redirect/email-template settings and Google flow were not changed. Email-code sign-in remains the reliable primary path; email links may open finance.

Checks: 17 domain/auth/database tests and five DOM interaction tests pass; production TypeScript/Vite build passes. Isolated database tests verify cross-user rejection, invalid-occasion rejection, feedback isolation and Wardrobe-clear preservation of tracker/Auth records. Live transactional item/recommendation/rating checks passed and were rolled back. Browser layout and signed-in end-to-end behavior must not be described as verified.
